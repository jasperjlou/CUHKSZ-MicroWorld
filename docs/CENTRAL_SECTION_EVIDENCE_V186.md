## 新剖切解决了什么

对已恢复的旧下园 GLB 做 X=-440、X=-400、Z=160 三条精确平面求交，分别生成 783、1309、1572 条截线；三个图均已查看。这与 V152 的 77 个垂直交点探针不同，没有重复原探针扫描。

在 X=-440 的剖切中，后侧道路为旧 Y≈31.24，靠门的平台顶约 33.04；同一剖面明确画出约 29.74–33.04 的厚底板，以及上方 43.04、52.24 等构件。X=-400 中还能看到外部地面、阶梯与内部台地的分别衔接。**30.04/33.04 等邻近交点不能再当两个独立使用楼层**，大面下方的 26.78 也不能不经空间核对就称为当前馆内 G 层。

原数据没有统一到现模型的单位/原点/楼层名；某个剖面没有截到下层房间也不证明整个旧馆缺该层。旧资产只支持空间高低与结构候选，不能直接把后路抬到当前 2F，亦不能为减少一排窄窗就降低整个玻璃大框。后门实景两排窄窗与模型三排的冲突继续明确保留，下一步必须匹配后门内外的同名空间。

分析脚本 `tools/library_sections_v186.py`；详细截线和 PNG 在本地 `references/legacy-gta-20261011/local-only/library-sections-v186/`。详细旧几何不提交/不随正式包分发。

已下载并查看原分辨率 7008×4672 的 `DSC02494.JPG`、`DSC02471.JPG`、`DSC02518.JPG`。近景可见浅色方砖、灰色竖向栏板的上行台阶、圆柱与暖色竖向构件，以及对面红格栅/灰色楼体；人群遮挡较多，不能据此直接测量梯宽、梯高或唯一判断照片里的梯属于哪一栋楼。三图 EXIF DateTimeOriginal 均为 2026-09-07（11:39:46、11:47:42、11:58:24），与报道活动时间一致；相机时钟未独立校准。拍摄元数据、活动日期和文章发布时间分别记录，不从上传目录推断。

这些照片提供了较新的 C–D 连接端点证据。下一步先把灰栏梯、圆柱、暖色竖向构件和对面红格栅与既有 1F 入口全景、学生中心前廊图纸及用户照片匹配，锁定照片所在侧和梯的上端，再成批修局部连接。

## 一个来源定位纠错

现有 `scene_catalog.json` 与 `scene_links.json` 中：`pano_id=70037189` 对应 **scene_id=116440797，Graffiti Wall**。部分 V149/V150/V180 来源把 panorama 资源 ID 填进了 `scene_id` 查询参数。正确入口是 [官方全景 116440797](https://campusvr-en.cuhk.edu.cn/?scene_id=116440797)，旧图片内容及哈希不变。

本批记录纠错而不重写历史验收收据。邻近 Road by Library 为 scene 116443792 / pano 70040614；馆内 Ground 为 scene 41566367、41566368，2F 主入口为 41830774。以后按场景 ID 导航，不能将资源 ID 当场景 ID。
